# Spike S-3 — ADS on three OSes: not run

| | |
|---|---|
| Date | 2026-10-11 (M1 acceptance review) |
| Question (07 §11) | Does ADS build as a shared library and work behind `DockHost` on Windows, Linux and macOS? |
| Status | **Not run.** ADS is not in the tree: D-147 vendors every dependency and needs the user's approval for each download, and no download of ADS was asked for or approved in M1. |
| Consequence | `DockHost` runs on its `QDockWidgetBackend` on every OS (`libs/widgets/README.md`, "Shell and docks"). AC-M1-13 is met on that backend only. D-153 (DECISIONS.md A.12, proposed) records this and asks the user to choose. |

## What was checked instead

- AC-M1-13's contract on the `QDockWidget` backend, offscreen on Windows (`widgets.tst_dock_host`): save and
  restore of a perspective, auto-hide (fly-out and collapse), float and re-dock, toggle and the close button,
  refusal of a perspective written by another backend, and the `layout-1` round trip. ESC back to the
  worksheet and Reset Dock Windows run in `widgets.tst_main_window`.
- The backend seam (`IDockBackend`) through which an ADS backend would be added. `ESSES_DOCK_BACKEND` selects
  the backend at run time once there is a choice, and `layout-1` records which backend wrote a perspective.

## To run the spike (M2, after the user approves the download)

1. Vendor ADS at a pinned tag under `third_party/qtads/` per D-147 (licence file, `third_party/README.md` row,
   `NOTICES.md`, `REUSE.toml`) and build it as a shared library (D-026, D-119; LGPL-2.1).
2. Implement `AdsBackend : IDockBackend` and run `widgets.tst_dock_host` on both backends on the three CI
   runners (`qt-app`), plus an interactive check on Windows.
3. Pass: build and Qt Test green on all three runners and no visual breakage on Windows; ADS becomes the
   default where it passes. Fail on an OS: that OS keeps the `QDockWidget` backend (D-026's fallback rule).
