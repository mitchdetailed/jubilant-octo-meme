## What was built

- ADS 5.1.1 (tag v5.1.1), downloaded on 2026-10-11 with the user's approval and vendored unmodified under
  `third_party/qtads` (archive SHA-256 and tree digest in `third_party/README.md`; LGPL-2.1-or-later, `NOTICES.md`).
- Built by its own CMake project (`cmake/qtads.cmake`: `BUILD_STATIC OFF`, `BUILD_EXAMPLES OFF`,
  `QT_VERSION_MAJOR 6`) as the shared library `qtadvanceddocking-qt6` (`qtadvanceddocking-qt6d.dll` in Debug),
  output in `<build>/bin` beside every executable and test; alias `esses::qtads`, linked privately by
  `esses_widgets` only.
- `AdsBackend : IDockBackend` (`libs/widgets/include/esses/widgets/shell/ads_backend.hpp`,
  `src/shell/ads_backend.cpp`): `CDockManager` as the host's central widget, the worksheet area as ADS's central
  dock widget, one `CDockWidget` per dock (tabbed by registry area), floating containers, auto-hide side bars
  with the fly-out of 06 §3.3 item 5, close/open, perspectives as a JSON envelope around
  `CDockManager::saveState`, Reset Dock Windows. The state is read back from ADS, so ADS's own buttons, tabs and
  drags are seen too.

### Offscreen notes

The `offscreen` platform has no window manager, so the tests check what does not depend on one:

- A floating dock is checked as being in a visible top-level window of its own, never by position or size.
- QMainWindow keeps the hidden tabs of a tabbed dock group visible but moved out of sight, so "the dock is on
  screen" is `isVisible()` with a non-empty visible region, after the pending layout.
- Re-docking a floating ADS window by drag needs real mouse moves over drop overlays; the test drops it with
  `CDockManager::addDockWidget`, which is what ADS's drop does, and checks that `DockHost` hears of it.
- Making a window active is asynchronous; focus checks wait (`QTRY_*`). `DockHost::focus` activates the dock's
  window when another one (a floating dock) is active.
