# Maths compatibility readings

Esses reads maths written for the reference tool's expression language unchanged (D-020). Where that tool's
documentation leaves a behaviour open, Esses takes a reading, records it here with its id, and tests it. A
reading marked *chosen, not observed* has not been compared with the reference tool yet (D-005 (3), D-038);
an observation that disagrees changes the reading, its test and this table together. The design of the
language is `docs/design/03_MATHS_ENGINE.md` §2-§3; the switches `MathsCompat` (project option
`options.maths.compat`) are part of every definition hash (03 §7.2): the function aliases directly, the power switch
through the canonical text of the parse it changes (D-185 (f)).

Each row names the tests that pin it: `parser`, `checker` and `eval` are `parser_tests.cpp`,
`type_checker_tests.cpp` and `compile_eval_tests.cpp` under `libs/maths/tests/lang/`; a name in code type is a case
file `tests/maths/cases/<id>.case.json` (schema `maths-case-1`, 03 §14.1, AC-M2-02). The expected values of the case
files come from `tools/maths_ref.py`, an independent per-sample reference written from 03 §5 and from this table,
never from the kernels (D-041); `python -I tools/maths_ref.py --check tests/maths/cases` confirms the committed files
are what it generates, and the Catch2 test `maths.maths cases: every tests/maths/cases/*.case.json passes` runs them
through `compile` and `evaluateWhole`.

maths_corpus_check.py --compat-doc docs/maths-compat.md` fails when another `E-*` code remains in the corpus.
