### 2.7 Pull request #1 CI run (2026-10-12)

Run 38202115135 on pull request #1 (`m1-walking-skeleton` at 78d4692, merged into `main` by GitHub) failed
`lint`, `core (macos-14)`, `qt-app (ubuntu-24.04)` and `qt-app (windows-2022)`; a review comment asked for the
Windows GUI executable's console output. Each item, its cause and its fix:

**`lint`, DCO sign-off.** On `pull_request` the checkout is GitHub's synthetic merge of the pull request into its
base, so `git rev-list origin/main..HEAD` listed that merge commit (a81e65e), which nobody authored, beside
78d4692. The step now checks `git rev-list --no-merges origin/<base>..<head SHA of the pull request>`: the pull
request's own commits, merges left out. On a scratch repository shaped like a pull request's merge ref (a signed
branch commit, a merge of the base into the branch, a second signed commit, the synthetic merge) it checked
exactly the two authored commits; on this repository it reports 78d4692. The requirement is unchanged: 78d4692
carries no `Signed-off-by:` line and the step fails on it until the maintainer decides how to sign it off (the
sign-off is the author's own statement, so it is not added here).

**`core (macos-14)`, `base.mapped file: a page fault inside the view becomes fail(Io)`.** The test maps a
four-page file, truncates it to 0 and reads the third page inside `guarded()`; on macOS the read returned without
any signal and `guarded()` reported success. POSIX leaves this case open: `mmap()` requires `SIGBUS` only for
whole pages beyond the end of the object, and the effect of reading a part of the mapping whose file was later
shortened or grown is unspecified. Linux documents `SIGBUS` for it (`mmap(2)`); macOS evidently keeps serving the
pages that were already resident (the open's quick hash had read all four). `MappedFile` now keeps its descriptor
open on POSIX, and `guarded()` `fstat()`s it after the routine returns: a file now shorter than the view is
`fail(Io)` ("the mapped file was truncated while it was being read") on every POSIX system, whether or not a
signal was raised, and a `SIGBUS` inside the view stays `fail(Io)` as before. Windows is unchanged (an in-place
writer gets a sharing error; `EXCEPTION_IN_PAGE_ERROR` is still caught). New test `base.mapped file: a truncation
is fail(Io) even when no removed page is touched` (POSIX). The POSIX branch cannot be compiled on this machine
(no Linux compiler in WSL either); it was reviewed by hand and the `core` jobs on Linux and macOS run both tests.

**`qt-app (ubuntu-24.04)`, Qt 6.12 deprecations.** GCC 13 stopped at `QSortFilterProxyModel::invalidateRowsFilter()`,
which Qt 6.12's header marks `QT_DEPRECATED_VERSION_X_6_13`: Qt is built with `QT_WARN_DEPRECATED_UP_TO`
0x070000, so a project sees every deprecation its headers carry, including those scheduled for later releases,
and `-Werror` turns them into errors. Both call sites (the Channels and Messages filters) now use
`beginFilterChange()` (Qt 6.9) and `endFilterChange(QSortFilterProxyModel::Direction::Rows)` (Qt 6.10) under
`QT_VERSION >= QT_VERSION_CHECK(6, 10, 0)`, with the filter's fields changed between the two calls, and keep
`invalidateRowsFilter()` for older kits. To find the rest before CI does, the declarations that Qt 6.12.0's public
headers mark deprecated from 6.8 on (`QT_DEPRECATED_VERSION_X_6_8` to `_6_16`, `QT_DEPRECATED_SINCE(6, n)` blocks,
`Q_DECL_ENUMERATOR_DEPRECATED_X`, `QT_DEPRECATED_X`) were listed from 681 public headers of qtbase 6.12.0 (Core,
Gui, Widgets, Test, PrintSupport and OpenGL among them; we use no other Qt repository), and each name was
searched for in our sources (ADS is built without warnings and is not ours). One more use: `widgets.tst_main_window` builds a `QDragEnterEvent` from
a `QPoint`, a constructor deprecated for 6.16 now that 6.12 adds a `QPointF` one; it is chosen under
`QT_VERSION_CHECK(6, 12, 0)`. The other listed names are unused or not the deprecated overload
(`QRegularExpression::match` is called with a `QString`, `QDateTime::fromMSecsSinceEpoch` with one argument, and
the only `stateChanged` is `DockHost`'s own signal). The Qt 6.7 branches build here (MSVC, Clang 17); the 6.10
and 6.12 branches compile in `qt-app`.

**`qt-app (windows-2022)`, installing Qt 6.12.0.** aqtinstall 3.3.0 (install-qt-action's default `==3.3.*`, and
the newest release on PyPI) looked for `windows_x86/desktop/qt6_6120/qt6_6120/Updates.xml` and stopped with
"Failed to locate XML data for Qt version '6.12.0'". From Qt 6.11 the Windows x64 desktop repository has one
directory per toolchain instead (`qt6_6120/qt6_6120_msvc2022_64/`, `_mingw`, `_llvm_mingw`,
`_msvc2022_arm64_cross_compiled`, each with its `Updates.xml` and checksum); the Linux and macOS repositories keep
the nested `qt6_6120/qt6_6120/`, which is why ubuntu installed. aqtinstall issue 959 reported the change for
6.11.0, and its pull request 1000 (merged 2026-03-24) reads the new layout, but no release after 3.3.0
(2025-06-02) exists. `ci.yml` now sets install-qt-action's `aqtsource` to aqtinstall's master branch at commit

**Review: `esses --version` from a Windows terminal.** `esses` is a GUI-subsystem executable: Windows gives it no
console and, unless the caller redirected them, no standard handles, so `--version`, `--help`,
`--dump-commands` and parser errors printed nothing in a terminal. `main()` now starts with `ParentConsole`
(Windows only): when stdout or stderr has no handle, `AttachConsole(ATTACH_PARENT_PROCESS)` attaches to the
terminal's console and the streams without a handle are reopened on `CONOUT$`; redirected streams (a file, ctest's
pipes) are kept. Started from Explorer the parent has no console, the call fails and nothing changes, so no
console window appears. Before the GUI runs (any start without `--version`, `--help` or `--dump-commands`) it
reopens those streams on `NUL` and calls `FreeConsole()`, so the terminal's Ctrl+C or closing it cannot end the
application. New ctest `app.version_console` (Windows): `esses_console_probe` creates a pseudo console (ConPTY),
runs a copy of itself inside it as the shell, which starts `esses --version` the way a shell does (no inherited
handles, no new console), and requires the version line in the pseudo console's output; no window opens.
Against the `esses.exe` of a build without the change the probe fails (the console stays empty); with it,
it passes, and `--help` reaches the console too. `app.version` (ctest's pipes) still passes.

**`qtmodel.tst_source_loader` with Clang 17 (§6 item 2).** Not a compiler difference but a race in the test:
instrumented, the Clang build had already seen one `sourceReplaced` (snapshot version 0 to 1) when line 118
compared `SourceLoader::source(id)` with the published snapshot. The publication prefetches Corr Speed, and phase 2
(stint / pitStop) then replaces the snapshot; without the slower MSVC debug runtime the whole chain completes
within the wait slice in which the publication arrived, as it would on ubuntu and macOS. The test now expects the
published snapshot when no replacement was observed, otherwise the newest replacement (same id, higher version).

## 5. Deviations from the design

Recorded as proposed ADRs in `DECISIONS.md` A.12; the affected documents are updated where an entry says so.

1. **Dock backend** (07 §4.1, AC-M1-13, D-026, D-044, D-119, D-147): decided by the user on 2026-10-11 (D-153). ADS
   is the default backend, vendored (not fetched) and built by its own CMake project as `qtadvanceddocking-qt6`
   (`esses::qtads`, where 08 §3.7.3 has `qt6advanceddocking` and `esses::ads`); the `QDockWidget` backend is kept
   on every OS, not only where S-3 fails, selectable at run time and at build time (`ESSES_DOCK_BACKEND`).
2. **`alternateList` in M1 and its `Speed` entry** (D-016, D-044, 03 §9.1, 07 §4.1): D-154.
3. **Benchmarks** (07 §4.5): the budget rows come from `esses-plot-bench` and `esses-open-bench`; no `esses-cli
   bench`. D-155.
4. **Shell placement** (01 §2.1): `MainWindow`, `DockHost`, `KeyEventRouter`, `CommandActions` and `LayoutFile` live
   in `esses_widgets`; `esses_app` is `main()` only. D-156.
5. **`DistanceIndex::timeAt`** (D-016, 04 §3.1): exact first reach between the 0.25 m steps; `tAtD[]` unchanged.
   D-157.
6. **Marker order** (02 §4.3 behaviour 8): `EOL` before `SOL` at equal times, plus the beacon-pair rule's
   implied `EOL` and data-end virtual `EOL`. D-158 (review fix R-30/R-31).

API-level departures (added accessors and hooks, argument types, helper classes the documents name without
declaring) are listed in the "Deviations from the design text" section of each library's `README.md`
(`analysis` 6, `maths` 11, `model` 9, `plotcore` 6, `project` 8, `qtmodel` 15, `qtrender` 6, `widgets` 13,
`apps/cli` 4). The M1 additions from this review: `TaskPool::queuedTasks`, `AppRuntime::removeSink`,
`ComponentWidget::cancelTransient`/`sizeThrottleActive`, `WorksheetCanvas::layoutThrottleActive`/
`keptWorksheetCount`.
